# Production Auto-response Incident — มะลิปัง

วันที่: 13 สิงหาคม 2026
สถานะ: **RESOLVED**

## ผลกระทบต่อลูกค้า

ข้อความทั่วไปของลูกค้าถูกตอบอัตโนมัติด้วยข้อความที่ทำให้เข้าใจว่าไม่มีผู้ดูแลตอบบัญชี และบางข้อความได้รับแบบฟอร์มสั่ง/จองล่วงหน้าที่ยาวและไม่เกี่ยวข้อง ส่งผลให้ลูกค้าอาจหยุดสอบถามหรือเข้าใจผิดว่าต้องกรอกออเดอร์ทันที

ข้อความที่ทำให้เข้าใจผิด:

> ขอบคุณที่ส่งข้อความถึงเรา
> ต้องขออภัยเป็นอย่างยิ่งที่บัญชีนี้ไม่สามารถตอบข้อความใดๆ ได้
> โปรดรอรับข่าวสารใหม่ๆ จากเราผ่านช่องทางนี้

## สาเหตุหลัก

- กฎ `Default` เป็น Fixed response แบบไม่กำหนดเวลาและตรงกับทุกข้อความ
- กฎ `Add Friend` แม้ชื่อสื่อถึงการเพิ่มเพื่อน แต่เป็น Fixed response แบบไม่กำหนดเวลา ไม่มี keyword และตรงกับทุกข้อความเช่นกัน
- `Add Friend` ส่งแบบฟอร์มยาวที่ขึ้นต้น `🧾 สั่ง/จองล่วงหน้า (คัดลอกไปกรอกได้เลย)` จึงปรากฏหลังข้อความที่ไม่เกี่ยวกับการสั่งซื้อ
- Chat เปิดอยู่ และวิธีตอบระหว่าง response hours เป็น Manual chat + auto-response ทำให้กฎ global ทำงานร่วมกับการตอบของพนักงาน

## สถานะก่อนแก้ไข

- Chat: ON
- Greeting: ON
- Response hours: ON (Asia/Bangkok; ครอบคลุมตารางทั้ง 7 วัน)
- ระหว่าง response hours: Manual chat + auto-response messages
- `Default`: ON, Fixed response, Always, match ทุกข้อความ
- `Add Friend`: ON, Fixed response, Always, match ทุกข้อความ
- `Menu`: ON, keyword `เมนูขนมปัง`
- `Facebook อั่งเปา`: ON, keyword `อั่งเปา`
- Messaging API: Disabled
- Webhook: OFF/unavailable

## การแก้ไขที่ได้รับอนุมัติและดำเนินการแล้ว

1. ปิด `Default` → OFF
2. ปิด `Add Friend` → OFF

ไม่ได้แก้ไขข้อความ สร้างกฎทดแทน หรือส่งข้อความ Production เพื่อทดสอบ

## การตั้งค่าที่ตั้งใจคงไว้

- Chat: ON
- Greeting: ON
- Response hours: ON
- `Menu`: ON
- `Facebook อั่งเปา`: ON
- Messaging API: Disabled
- Webhook: OFF
- Rich Menu, profile, roles, permissions และ AI Chatbot: ไม่เปลี่ยน

## Rollback

Rollback ใช้เฉพาะเมื่อเจ้าของอนุมัติและมีเหตุผลชัดเจน:

1. ยืนยันบัญชีที่มองเห็นเป็น `มะลิปัง` และไม่มี `TEST`
2. เปิด Auto-response messages และตรวจชื่อ/เนื้อหาของกฎเป้าหมาย
3. เปิด `Default` หรือ `Add Friend` กลับทีละกฎตามที่เจ้าของอนุมัติ
4. ยืนยันสถานะ `In use` ของกฎนั้นเป็น ON
5. ทดสอบด้วยบัญชีเจ้าของโดยไม่ใช้ข้อมูลลูกค้าจริง

คำเตือน: ไม่แนะนำให้ rollback กฎใดกลับเป็น ON ในรูปแบบเดิม เพราะทั้งสองกฎ match ทุกข้อความ ควรแก้ trigger และทดสอบใน Test OA ก่อนเสมอ
