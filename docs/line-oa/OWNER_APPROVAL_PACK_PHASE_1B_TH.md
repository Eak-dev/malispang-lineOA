# Owner Approval Pack — Approved Knowledge Base (`Issue #8 / Phase 1B`)

จัดทำ: 29 สิงหาคม 2026 (Asia/Bangkok)

สถานะ: `OWNER REVIEW REQUIRED / ALL MANIFEST RECORDS REMAIN BLOCKED / NOT DEPLOYED`

เอกสารฉบับนี้เป็นจุดอนุมัติเดียวสำหรับ Approved Knowledge Base ของ `มะลิปัง TEST` ตาม Roadmap Issue #9 และ Issue #8 เท่านั้น การทำเครื่องหมายในเอกสารยังไม่เปลี่ยน manifest หรือระบบที่ใช้งานจริง ต้องนำผลอนุมัติไปสร้าง manifest version ใหม่ ตรวจ checksum และทำ Owner UAT จาก frozen commit ก่อนข้อมูลจึงจะเป็น `APPROVED`

ขอบเขตของรอบนี้ไม่รวม Issue #6, deployment, การแก้ LINE OA `มะลิปัง TEST` หรือการเปิด/แก้ Production `มะลิปัง`

## วิธีอนุมัติรอบเดียว

1. ตรวจข้อความ exact, source และวันมีผล/วันทบทวนของแต่ละแถว
2. เลือกเพียงหนึ่งช่องต่อแถว: `APPROVE` หรือ `KEEP BLOCKED`
3. แถวที่ระบุ `Owner กรอก` ต้องใส่ค่า exact ก่อนเลือก `APPROVE`; ห้ามอนุมัติช่องว่าง
4. หากต้องแก้ข้อความ ให้เขียนข้อความทดแทนแบบ exact ในคำตอบอนุมัติ ห้ามใช้คำว่า “ประมาณ”, “ตามเดิม” หรือ “เหมือนในรูป”
5. Owner สามารถอนุมัติ Pack ทั้งฉบับในคำตอบเดียวด้วยแบบฟอร์มท้ายเอกสาร

คำจำกัดความ:

- `CANDIDATE` = มีหลักฐาน TEST/Owner-approved source ให้ตรวจ แต่ยังไม่เป็น record `APPROVED` ใน Issue #8
- `BLOCKED` = ห้ามบอตตอบข้อมูลธุรกิจหมวดนั้นจนมี exact value, source และช่วงมีผลครบ
- วันผ่าน UAT หรือวันที่เอกสารถูกสร้างไม่ถือเป็น effective date โดยอัตโนมัติ

## ข้อขัดแย้งและข้อมูลที่ Pack ไม่ยกสถานะเอง

- ข้อมูล `TEST_SEED` ไม่ใช่ authoritative source และไม่ถูกเลื่อนเป็น `APPROVED`
- เวลาเปิดมีหลักฐานขัดกัน จึงห้ามเลือกค่าหนึ่งเอง
- เบอร์โทรและข้อความในภาพเมนูไม่ถูกตีความเป็น contact/price database โดยอัตโนมัติ
- `Facebook อั่งเปา` ไม่ถูกใช้เป็นโปรโมชั่นปัจจุบันเพราะไม่มี validity window ที่ยืนยัน
- Reward Card ใน OA-12 เป็นของ `มะลิปัง TEST` เท่านั้นและมีกติกาต่างจาก Production baseline
- fallback มีสองสำนวนใน codebase; Pack เสนอ Worker wording ที่ใช้งานใน TEST ให้ Owner เลือกแบบ exact แต่ยังไม่แก้ code ในรอบเอกสารนี้

## ขั้นตอนหลัง Owner อนุมัติ (ยังไม่เริ่มในรอบนี้)

1. แปลงเฉพาะแถวที่อนุมัติและมี dates ครบเป็น immutable manifest records พร้อม version/checksum
2. คงแถวที่ไม่อนุมัติเป็น `BLOCKED`; ห้ามใส่ customer-facing answer ใน blocked record
3. รัน schema, stale/conflict, fail-closed, handoff และ regression tests
4. freeze commit แล้วทำ Owner UAT ภาษาไทยของ Issue #8
